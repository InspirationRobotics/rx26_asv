# Every process the Task 1 sim rig starts inside crsd-sim, as pkill -f patterns.
#
# ONE LIST, READ FROM BOTH ENDS. task1_sim_up.sh clears the rig before it starts
# it, and nodes_down.sh clears it on the way out. Those were two hand-kept
# copies; a node added to one and not the other survives a shutdown and the next
# run comes up with two publishers on the same topic, which looks like a
# perception bug and is not one.
#
# MATCH THE INSTALL PATH, NOT THE `ros2 run` LINE. `ros2 run pkg node` EXECS the
# binary under install/pkg/lib, so by the time the node is doing anything the
# string "ros2 run crusader_fcu" appears in nobody's argv.
#
# THESE PATTERNS MUST NEVER APPEAR ON A COMMAND LINE. `pkill -f` matches the
# argv of the shell running it too, so `docker exec ... pkill -f crusader_bt/lib`
# kills its own shell -- exit 143, no output, indistinguishable from a hang.
# Reading them from this file into a shell variable is what keeps them out of
# argv, and is the only reason this is a file rather than a loop.
